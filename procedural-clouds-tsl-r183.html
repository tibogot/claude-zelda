Same cloud math as procedural-clouds-three-r183.html: run node scripts/gen-procedural-clouds-tsl-wgsl.mjs after editing _wgsl_body.txt.
Compute uses WGSL_TSL_LIB (noise + Voronoi + density write). Fragment uses WGSL_TSL_FRAG_LIB (uniforms + ray march + textureLoad only) so the GPU does not type-check unused WGSL in the fragment module.
If the GPU rejects a shader, the console shows [WGSL] lines with source context. Three also compiles internal passes (e.g. outputColorTransform, ~1k WGSL). Your cloud material uses material.name as the shader label (ProceduralCloudQuad here): use window.__PC_FRAGMENT_BY_NAME["ProceduralCloudQuad"] or window.__PC_MAIN_FRAGMENT_PROGRAM (longest WGSL seen).
Optional: add ?pcShaderLog=1 to the URL for per-compile fragment logs (ProceduralCloudQuad vs outputColorTransform).
